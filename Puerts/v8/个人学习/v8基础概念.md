# Isolate 与 Context
可以将这两个东西理解为
- **Isolate = 一个独立的 JS 虚拟机实例**
- **Context = 这个虚拟机里的一个“全局环境/沙箱”**

## Isolate简述
在cpp项目中开一个v8虚拟机，实际上就是**new一个新Isolate**
Isolate承载了GC, 对象系统, 堆, JIT, 事件循环(微队列), builtins 等结构和功能，这些大部分不是细粒度线程安全的，因此
> Isolate(js执行)是**单线程**的，同一时刻，只有一个线程能进入Isolate

在Chrome中，多个页面就是多个Isolate，作为安全隔离；
nodejs的`worker_threads`多线程,就是开了多个Isolate，每个 Worker 线程都会创建自己的 V8 Isolate来达成多线程的方式，这也是为什么node中每个worker_thread中变量不可共享。
```
Isolate 内部结构 
├── Heap  
├── GC  
├── Stack limit  
├── HandleScope system  
├── Builtins  
├── Context list  
├── Microtask queue  
├── JIT compiler  
└── Profiler
```

## Context
一个Isolate可以有多个Context，Context代表一个**JS 全局执行领域(环境)**
### Global Object
每个Context中都有一个不同的 `Global Object
如Chrome中的window，nodejs中的globalThis都叫做`Global Object`，每个Context中都有一个，`Global Object`并不代表 "全局对象"，而是 **代表全局** 的对象
某个 `Global Object` 实际上在一个Isolate的不同 Context 中是可以互相访问的

就比如chrome中同源的`iframe` , 其本质上是开了一个新的Context，这也是为什么我们在页面的js执行中可以拿到`iframe` 中的 window变量，也就是那个`iframe`中的`Global Object`

v8其实本身不知道什么window，globalThis，它只知道那个`Global Object`

```cpp
v8::Local<v8::Context> context;
// 获取这个context的GlobalObject
v8::Local<v8::Object> global = context->Global();
```

### JS 执行领域

- 编译/执行js
```cpp
auto context = v8::Context::New(isolate);  
v8::Context::Scope scope(context);  
auto source = v8::String::NewFromUtf8Literal(  
	isolate,  
	"let x = 1; x + 2"  
);  
auto script = v8::Script::Compile(context, source).ToLocalChecked();  
auto result = script->Run(context);
```
script 的执行环境就是 context；
这里执行的是一个普通script，在v8中，还有ESModule的模块js执行，比如
```js
// 代码中有export或者import关键字的js，都是ESModule js
export const x = 1;
```
但是v8不会自己做判断，需要宿主决定然后告诉v8


- ESModule
v8负责ESM中的语法解析，模块实例化，模块执行，模块作用域；
而在模块中，不属于v8做的是**路径解析和文件读取**
```js
import x from 'something'
```
`"something"` 到底怎么变成文件路径？这里就是nodejs/chrome/puerts 来做的事情

- Lexical Environment (词法环境)
Context中包含了词法环境，在Isolate堆中保存的obj，变量绑定在Context中 
要把变量拆成两部分，变量名binding 和变量值 value 来看；
```js
// 两个变量指向同一个对象
// a的value存储在堆中，b=a，同一个value在Context中保存了两个binding
let a = {};  
let b = a;
```


> Isolate提供VM级资源，如heap,gc,jit；
   Context提供语言级执行环境，如global object,词法环境，闭包根，prototype chain；
# 句柄, Local, Global, Persistent, Scope, Maybe

在 v8 里，`Handle（句柄）` 是 v8 管理js对象生命周期的核心机制。因为v8的GC会移动对象地址，所以cpp代码不能长期保存裸指针，必须通过 Handle 间接访问。
Local, Global, Persistent都是 `Handle`
这些概念本质上是在解决C++如何安全地引用JS 对象；只有在C++层Embedding js层的时候才有用

## Local和Scope
`v8::Local<v8::Object>` 为一个临时句柄，生命周期由HandleScope控制，其非常轻量，Scope销毁后自动释放该句柄，不能跨函数长期保存，GC安全

```cpp
void Foo(v8::Isolate* isolate) {  
	v8::HandleScope scope(isolate);  
	v8::Local<v8::Object> obj = v8::Object::New(isolate); 
} // scope结束，obj失效
```
scope 销毁后 -> Local handle 被回收
js对象没有被销毁（由gc识别引用，判断释放），只有这个临时句柄被销毁，打个比方就像SharedPtr销毁了一个，引用控制少了一个
> Local 必须存在于某个 HandleScope 中。

HandleScope是一个“栈帧”，内部维护一个handle table，Local实际上是占用了handle table的某个槽位，scope被析构后，整个槽位全部释放

但是在js调用cpp时，假如我们要返回一个`v8::Local<v8::Object>` 是不需要创建一个scope的，因为此时v8 在进入callback前已经创建好了HandleScope
## Global,Persistent
Global和Persistent都是v8给C++的一些长期对象Handle，他们不会被GC回收
Persistent就像cpp中new 出来的裸指针，需要显式reset来delete掉，此外还有UniquePersistent，析构时自动 Reset
Global是可共享的持久句柄，比如Global可以拷贝，UniquePersistent只能移动


## Maybe
在js中，是有错误/异常的，如果在cpp中执行了一个js函数，然后这个js函数抛出异常，C++ 层不能假设一定成功
- `MaybeLocal<T>`
```cpp
// Obj用MaybeLocal
MaybeLocal<Value> maybeObj = obj->Get(context, key);   
Local<Value> Objvalue;  
if (maybeObj.ToLocal(&Objvalue)) {  
// success  
} else {  
// exception  
}
// 基本数据用Maybe
Maybe<bool> ok = obj->Set(context, key, value);
if (ok.IsNothing()) {  
// exception  
}
bool success = ok.FromJust();
```
一般从cpp调用js侧的函数或者获取js侧的变量，v8这里api基本上都是返回的Maybe/MaybeLocal

Data = V8世界的一切  
Value = JS中的值  
Object = JS对象  
Function = JS函数对象
1.  v8::Data
`v8::Data` 是所有v8runtime对象的根基类，它本身没什么功能。
意义是：统一 GC 管理Handle 体系与类型识别
v8::Context也是继承自v8::Data,只不过其`Global Object`是一个v8::Object
2. v8::Value
v8::Value代表任意 JavaScript 值
3. Primitive系列
基本可以理解成
> “JavaScript 的原始值（primitive value）”

也叫做基本数据类型，number  string  boolean  symbol  bigint  null  undefined，都是不具有对象身份的值；他们不可变，按值传递
但是基本数据类型都有包装类型，在访问其属性/方法的时候有临时的装箱拆箱
```js
let str = "abc";
str.length;
let num = 1234.111
num.toFixed()
```
4. Object系
除了Primitive,和External,其它的都是Object，包括
```js
{}  
[]  
function(){}  
new Date()  
/abc/  
new Map()
```
5. External
用于JS对象绑定C++对象，这样在JS对象中就可以持有native pointer了，在puerts中很重要，用于绑定UE里对象和js object
>A JavaScript value that wraps a C++ void*. This type of value is mainly used * to associate C++ data structures with JavaScript objects

在v8::Object中有一层叫做`Internal Field`，专门用于存储这个Obj的额外信息
```cpp
/**  
Gets a 2-byte-aligned native pointer from an internal field. 
This field * must have been set by SetAlignedPointerInInternalField, 
everything else * leads to undefined behavior. 
*/
V8_INLINE void* GetAlignedPointerFromInternalField(int index);

/** Sets the value in an internal field. */  
void SetInternalField(int index, Local<Value> value);
```
一般想要在Object中存一个native pointer，路径是 v8::Object->Internal Field  -> External -> C++ Object

在js获取/调用原生时，我们拿到的obj 实际上不是JS对象包裹C++对象，而是JS对象里存了一个指针


# FunctionCallbackInfo

v8::FunctionCallbackInfo是v8调用C++ 函数时，传给C++函数的 **调用上下文信息**
比如js中`Add(1, 2)` 在C++里的Add函数定义就是
```cpp
void Add(const v8::FunctionCallbackInfo<v8::Value>& args)
```
这里的args就是这次js调用的信息，包括
- 参数
- this
- 返回值
- isolate
- new.target
- 是否构造调用
- data
- holder
- receiver
例子：
```js
let res = person.say("hello")
```

```cpp
void Say(const v8::FunctionCallbackInfo<v8::Value>& args) {  
	auto isolate = args.GetIsolate();  
	  
	auto self = args.This();  
	// js中的person对象中的InternalField存了Person*
	auto* person = static_cast<Person*>(  
		self->GetAlignedPointerFromInternalField(0)  
	);  
	  
	v8::String::Utf8Value msg(isolate, args[0]);  
	  
	person->Say(*msg);  
	  
	args.GetReturnValue().Set(v8::Boolean::New(isolate,true));  
}
```
