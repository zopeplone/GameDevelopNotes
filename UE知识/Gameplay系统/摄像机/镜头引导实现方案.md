# 镜头引导实现方案

## 1 适用范围和定义

Camera Guidance 是正常 Gameplay 中引导玩家注意角色、机关或世界位置的表现能力，不负责移动、战斗或剧情状态。UGC Camera Focus 继续用于战斗锁定。

Soft Guidance 保持玩家 ViewTarget，调整镜头位置和旋转，让玩家与引导目标同时入镜；玩家主动操作镜头立即结束引导。无法在允许机位内实现构图时拒绝或结束。目标初始不在画面内时，需要先平滑进入构图；若要求从首帧起同时入镜，应拒绝起始构图不满足条件的请求。

Hard Guidance 创建一个逻辑上的 Guidance ViewTarget，目标 Actor 只作为引导目标语义使用；Camera Manager 的真实 ViewTarget 始终保持原来的玩家 ViewTarget。Modifier 直接修改最终 Camera Location 和 Rotation，不要求玩家入镜，也不被普通镜头输入打断。多段剪辑或角色演出交给 Sequence。

## 2 接口位置与职责

Camera Manager 暴露 RequestCameraGuidance、CancelCameraGuidance，以及输入和权限提交接口；请求结构 FCameraGuidanceRequest 携带 Preset 与目标。不新增 Component 或 Subsystem。

Manager 只持有一个 Guidance Modifier 实例，负责接口转发和注册。真实 ViewTarget 始终保持玩家 ViewTarget；Manager 不显式推进 Modifier，也不切换 ViewTarget。不保存引导阶段、目标、优先级或计时。

Guidance Modifier 保存绝大部分逻辑和全部引导运行时状态：请求校验、权限与优先级判断、目标解析、Preset、Turning/Holding/Ending、构图、追踪、输入打断、移动交接、恢复目标与清理。Modifier 决定什么时候切换/同步，Manager 执行对应操作。

状态、目标和时间全部在 Modifier 的 ModifyCamera 中推进；ModifyCamera 同时应用镜头结果。ProcessControlRotation 负责消费 Modifier 产生的 ControlRotation 同步请求。只有真实 ViewTarget 过渡时，ModifyCamera 可能针对不同 POV 重复调用；当前版本在文档中提醒，代码暂不做帧去重。

## 3 数据资产内容

UCameraGuidancePresetDataAsset 保存 Soft/Hard 模式、请求优先级、进入和退出时间、转向曲线、保持时间、目标追踪设置、FOV、画幅安全边距、目标包围范围、最小/最大机位距离以及 Hard 机位距离和角度。

具体目标、计时、输入状态和返回 ViewTarget 由 Modifier 实例持有，不写入共享资产。第一版 Soft 始终允许镜头输入打断，Hard 始终不允许。UGC 的完整 CameraDataAsset 不作为引导请求栈使用，也不修改战斗 Focus 的运行配置。

## 4 流程

1. 业务提交请求，Manager 转发给 Modifier。
2. Modifier 验证资产、目标、权限和构图可行性，并进行优先级仲裁。
3. 接受后保存运行状态。Soft 保持玩家 ViewTarget；Hard 由 Modifier 使用逻辑 Guidance ViewTarget 目标，但不调用 SetViewTarget，不改变 Camera Manager 的真实 ViewTarget。
4. Modifier 推进入场、保持和退出阶段，计算位置与旋转；ModifyCamera 应用结果。
5. 正常完成、取消、目标失效或 Soft 输入打断后，停止目标追踪并进入必要的交接。
6. Modifier 在 ModifyCamera 中完成 Returning；完成后设置待同步旋转，ProcessControlRotation 消费该结果并由 PlayerController 写回 ControlRotation。

高优先级请求替换低优先级请求，同级或低优先级拒绝。被替换请求不排队、不恢复。代码参考暂不处理 Blend 期间的抢占，需进一步补全。

## 5 移动输入

角色移动继续读取当前 ControlRotation，以其水平朝向计算前后左右。输入系统把处理过死区的移动轴与镜头输入交给 Manager，再转给 Modifier；不能用角色速度判断是否有输入。

有移动输入时，Modifier 要求保持 ControlRotation，镜头位置与旋转独立变化。无移动输入时，Modifier 在最终相机计算完成后请求 Manager 将当前 Camera Rotation 同步到 ControlRotation。引导中途新开始移动，则保持该次输入开始时的控制旋转。

引导结束而移动仍持续时，停止追踪目标但保留独立镜头Returning 状态，避免角色或镜头跳转；玩家可以操作镜头。返回玩家构图完成后立即同步方向，再恢复正常相机关系。下一次移动使用新的 ControlRotation。Returning 期间玩家输入不阻止回切，也不延长 Returning 时长；返回玩家构图完成后立即同步 ControlRotation。

## Modifier 内部状态组织

建议按用途分组，而不是在 Manager 与 Modifier 各保存一份：

| 分组 | 数据 |
|---|---|
| 当前请求 | Preset 引用、目标弱引用、世界点、请求标识 |
| 执行 | 阶段、阶段时间、起始 POV、当前 POV |
| 构图 | 玩家边界、目标观察点、距离、角度、碰撞结果 |
| 输入交接 | 移动轴、镜头增量、是否持续移动、Returning 阶段完成条件 |
| 恢复 | 原 Gameplay ViewTarget、逻辑 Guidance ViewTarget 目标、退出起始姿态 |
| 权限 | 外部 Camera 权限快照、目标失效与结束原因 |

Preset 为只读配置。Modifier 内部可缓存本次参数，避免运行期间编辑资产造成突变。目标使用弱引用并在执行前验证；运行中的资产、代理对象需要被可追踪的引用持有。

## Manager 与 Modifier 的调度

推荐显式调度，避免引擎自动 ModifierList 与手动调用重复执行同一个 Guidance：

1. Manager 创建一个项目 Guidance Modifier，初始化 CameraOwner，但不额外注册到自动 ModifierList。
2. Manager 不调用 Advance，也不执行真实 ViewTarget Blend。真实 ViewTarget 过渡时可能出现多次 ModifyCamera 调用，当前版本暂不做帧去重。
3. Camera Manager 按普通 ModifierList 调用 GuidanceModifier::ModifyCamera。
4. ModifyCamera 在一次调用中推进状态、解析逻辑 Guidance ViewTarget、计算并写入最终 POV。
5. Returning 完成后设置待同步旋转；下一次 ProcessControlRotation 消费该结果，PlayerController 写回 ControlRotation。

保留原 UGC Modifier 链用于普通 Gameplay Camera。Guidance 自有生命周期与引擎 Alpha 不混用；取消请求调用 CancelCameraGuidance，不以 DisableModifier 代替。若以后改为自动注册，必须删掉手动 ModifyCamera 调用，并补齐 Blend 端上下文、禁用和跳过执行的处理。

## 相机修改与构图

Soft 的求解同时包含玩家包围范围和目标观察范围，根据 FOV、宽高比和安全边距计算可容纳双方的距离及朝向。Hard 只约束目标范围。

保持阶段持续重新解析目标，不能用初始世界点冒充移动目标跟踪。超出距离或碰撞约束时结束/拒绝，不承诺任何空间都存在可行机位。

最终 POV 覆写发生在基础 UGC 碰撞之后时，必须为新位置补做碰撞与遮挡检测。进入、保持、退出、移动交接的每个阶段都要检查；只检查目标机位不足以保证过渡路径安全。

该方案不使用 ProcessControlRotation 或 ModifyFullControlRotation 来输出自动引导旋转；这两个入口属于控制旋转链。Manager 根据 Modifier 的控制权判断阻止正常旋转链覆盖移动参考方向，ModifyCamera 独立输出镜头。

## ViewTarget 的生命周期

Hard 的逻辑 Guidance ViewTarget 与真实 ViewTarget 是不同概念：目标 Actor 只用于解析目标位置和追踪，不调用 SetViewTarget。Modifier 根据目标计算 Camera Location 和 Rotation，真实 ViewTarget 仍是玩家。

第一次引导记录 Gameplay 返回目标；后续抢占保留该目标，不能把旧 Guidance 代理记录为返回目标。若原目标失效，需根据当前受控 Pawn 决定回退。

上层权限接管时立即停止引导、不恢复旧目标；普通取消则执行退出流程。两种结束不能混淆。Pawn 更换、Camera Manager 销毁时需清理目标引用、逻辑目标和状态。

## 移动交接的实现要求

有移动输入时“保持 ControlRotation”指阻止自动引导旋转写入控制旋转，不是每帧恢复引导最初的角度。玩家中途松开并再次移动时，应以最新同步后的 ControlRotation 为参考。

Soft 输入打断后立即停止目标吸引，但持续移动需要保留独立相机交接层。Returning 接收玩家镜头输入，但不等待输入归零；达到 Returning 时长或构图完成条件后立即同步 ControlRotation。不要把“仍处于交接”误报为“仍在追踪引导目标”。

Hard 不切换真实 ViewTarget，直接由 Modifier 在 Returning 中回到玩家构图，避免按住移动导致镜头跳回。代码参考采用 Returning 固定时长回切；持续移动不会阻止回切，回切完成后由 ProcessControlRotation 消费待同步旋转。
