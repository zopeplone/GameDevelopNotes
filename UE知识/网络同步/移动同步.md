# Character Movement Component 中的网络移动

本文详细说明 Unreal Engine **Character Movement Component（角色移动组件）** 的网络移动机制。

角色移动组件是一个 Actor Component，为人形角色提供封装好的移动系统，包括行走、下落、游泳和飞行等常见移动模式。它还集成了完善的网络游戏支持：默认移动模式都已构建为可复制，并提供了创建自定义网络移动的框架。

## 角色移动基础

`UCharacterMovementComponent` 会预先附加到 `ACharacter` Actor 类，以及从它派生的所有 Blueprint。

在 `TickComponent` 中，组件调用 `PerformMovement`，根据当前移动模式和玩家输入（通常是 `APlayerController` 中的控制输入变量）计算世界中的期望加速度。计算完成后，组件将最终移动应用到所属角色。

虽然 `ACharacter` 派生自 `APawn`，但 Character 并不是简单地添加了角色移动组件的 Pawn。`UCharacterMovementComponent` 与 `ACharacter` 是配套设计的：`ACharacter` 会重写若干复制变量和函数，以专门支持 `UCharacterMovementComponent` 的复制。

## PerformMovement 与移动物理

`PerformMovement` 负责在游戏世界中实际移动角色。在非网络游戏中，组件每帧直接调用它；在网络游戏中，服务器和客户端的专用函数会调用它，在本地执行玩家移动，或在远程机器上重现该移动。

`PerformMovement` 会：

- 应用外部物理效果，例如冲量、力和重力；
- 计算动画根运动和根运动源产生的移动；
- 调用 `StartNewPhysics`，根据移动模式选择相应的 `Phys*` 函数。

每种移动模式都有自己的 `Phys*` 函数，用于计算速度和加速度。例如，`PhysWalking` 处理地面移动，`PhysFalling` 处理空中移动。若要调试具体行为，应直接查看这些函数。

如果一帧内移动模式发生改变（例如角色开始下落或与物体碰撞），`Phys*` 函数会再次调用 `StartNewPhysics`，让角色在新模式下继续移动。`StartNewPhysics` 和各个 `Phys*` 函数都会传递已经发生的迭代次数；`MaxSimulationIterations` 限制允许的最大递归次数。

## 移动复制概览

`UCharacterMovementComponent` 使用所属 Actor 的网络角色决定如何复制移动。三种网络角色如下：

| 网络角色                   | 说明                                                      |
| ---------------------- | ------------------------------------------------------- |
| Autonomous Proxy（自主代理） | 位于拥有它的客户端机器上，由本地玩家控制的角色。                                |
| Authority（权威）          | 位于承载游戏的服务器上的角色。                                         |
| Simulated Proxy（模拟代理）  | 位于其他能看到该远程角色的客户端上。该角色可能由服务器上的 AI 控制，也可能由另一台客户端上的自主代理控制。 |

复制过程在 `TickComponent` 中循环执行，每帧重复。角色移动时，网络中的各机器副本通过 RPC 互相发送移动信息；不同网络角色会按各自的执行路径处理这些信息。

### 一次移动复制流程

1. **自主代理（拥有者客户端）**：客户端本地控制自主代理，运行 `PerformMovement` 完成物理移动。
2. 客户端创建 `FSavedMove_Character`，记录刚刚执行的移动，并将其排入 `SavedMoves`。
3. 合并相似的 `FSavedMove`。自主代理通过 `ServerMove` RPC 将压缩后的数据发送到服务器。
4. **服务器**：接收 `ServerMove`，使用 `PerformMovement` 重现客户端移动。
5. 服务器检查执行移动后的自身位置是否与客户端报告的结束位置一致。
6. 若一致，服务器向客户端确认移动有效；否则通过 `ClientAdjustPosition` RPC 发送校正。
7. 服务器通过复制 `ReplicatedMovement` 结构，将位置、旋转和当前状态发送给其他客户端上的模拟代理。
8. **自主代理**：收到 `ClientAdjustPosition` 后，客户端重现服务器移动，并利用 `SavedMoves` 队列重新追踪后续步骤，得到新的最终位置；成功解决后，从队列移除已保存移动。
9. **模拟代理（其他所有客户端）**：直接应用复制来的移动信息，并用网络平滑改善最终视觉效果。

该流程让玩家控制自己的角色时尽量少受服务器干扰，同时让其他玩家看到的角色运动接近其真实运动。大部分复杂性集中在自主代理与服务器之间的预测和校正；模拟代理只需跟随服务器给出的状态。

## 角色移动复制详解

下面按步骤展开上述流程。多数项目不需要重写 `UCharacterMovementComponent`，但这些内容可用于实现类似功能或定位修改点。这里主要介绍普通移动模式；根运动以及以其他 Actor 为基准的移动有相似但不同的执行路径。

### 拥有者客户端上的本地移动

自主代理在 `TickComponent` 中本地处理并记录移动，然后发送给服务器重现和权威应用。

#### 构建客户端预测数据

自主代理创建 `FNetworkPredictionData_Client_Character` 对象 `ClientPredictionData`，用于记录移动以及处理服务器校正。其参数包括：

- 客户端与服务器通信时的时间戳；
- 已保存或待处理的移动列表；
- 服务器校正的保存信息；
- 指示如何应用校正的标志；
- 决定平滑行为的参数。

该对象还包含操作这些参数的辅助函数。完整的成员和函数见 `FNetworkPredictionData_Client_Character` API。客户端执行本地移动、准备发送移动以及处理校正时，会频繁读取和修改这些参数。

#### 重现服务器校正

在处理玩家输入或世界中的力之前，自主代理调用 `ClientUpdatePositionAfterServerUpdate`，检查服务器是否发送了校正。如果发送了，`ClientPredictionData` 中的 `bUpdatePosition` 为 `true`，角色就会通过客户端校正流程重现服务器发送的移动。服务器校正的细节见“处理客户端错误与校正”。

#### 执行并记录移动

自主代理在 `TickComponent` 中调用 `ReplicateMoveToServer`，而不是直接调用 `PerformMovement`。该函数在 `PerformMovement` 前后加入记录移动和向服务器提交移动所需的逻辑。

`FSavedMove_Character` 记录自主代理每个 tick 开始和结束时的状态；随后只有其中的最小必要数据会通过 `ServerMove` RPC 发往服务器，内容包括：

- 角色最终位置和旋转；
- 捕获到的移动输入；
- 速度和加速度；
- 从 `AnimMontage` 捕获的根运动信息。

`ReplicateMoveToServer` 完成 `PerformMovement` 后，会在客户端预测数据中创建名为 `NewMove` 的 `FSavedMove_Character`，并将其加入 `SavedMoves` 缓冲区。缓冲区按从旧到新的顺序排列，在移动提交给服务器前充当队列。相似移动会合并为一个 `FSavedMove_Character` 以减少带宽；`PendingMove` 保存等待与后续移动合并的移动。

移动获得确认（ACK）后会从缓冲区移除。服务器可以通过确认客户端位置有效直接 ACK；客户端也可以在处理服务器校正时 ACK。最近一次 ACK 的移动保存在 `LastAckedMove` 中，用于后续校正处理。

#### 向服务器提交移动

`ReplicateMoveToServer` 最后调用 `CallServerMove`，传入最新移动以及队列中尚未被服务器 ACK 的最旧移动。该函数完成提交前准备，必要时先提交旧移动，再调用合适的 `ServerMove` 函数提交最新移动。最终的 `ServerMove` 以不可靠服务器 RPC 的形式直接发送给组件所属的角色。

`ServerMove` 使用不可靠 RPC 有两个原因：

1. 正常游戏中调用频率很高，若设为可靠 RPC，可能耗尽可靠函数缓冲区并迫使玩家断开连接。
2. 已保存移动的缓冲系统会重新提交并评估传输中丢失的移动，提供类似可靠函数的保障，同时避免可靠 RPC 缓冲区溢出，并会丢弃过旧的移动数据。

### 服务器上的移动评估

服务器不会按游戏 tick 周期规律地执行移动，而是等待自主代理发来的 `ServerMove`。服务器端的 `ServerMove_Implementation` 会重建客户端移动并检查差异。不同类型的 `ServerMove` 会根据排队数据的种类而变化。

#### 构建服务器预测数据

权威角色移动组件创建 `FNetworkPredictionData_Server_Character` 对象 `ServerPredictionData`，其生命周期与角色相同。在 `ServerMove_Implementation` 中，该对象保存后续重现客户端移动所需的信息。服务器收到数据后会持续修改它，参数包括：

- 用于计算服务器 delta time 的时间戳；
- 待处理的客户端校正；
- 解决时间差异的标志；
- 表明服务器应 ACK 还是校正移动的标志。

完整成员和函数见 `FNetworkPredictionData_Server_Character` API。

#### 验证客户端时间戳

`ServerMove` RPC 包含移动发生时的时间戳。如果服务器与客户端时间戳差异过大，客户端时间戳会被视为过期，移动被丢弃；否则会标记该差异待解决，并由 `ProcessClientTimeStampForTimeDiscrepancy` 为下一步创建 delta time 覆盖值。

#### 计算 Delta Time

通常 delta time 来自当前 tick 与上一 tick 的时间差，但服务器上的角色不使用 `TickComponent` 计算移动。`ServerMove_Implementation` 调用 `GetServerMoveDeltaTime`，随着收到 `ServerMove` 动态计算。如果服务器预测数据标记为正在解决时间戳差异，则使用 `TimeDiscrepancyResolutionMoveDeltaOverride`；否则根据当前和上一个 `ServerMove` RPC 时间戳之差生成 delta time。为提高安全性，大部分计算使用服务器时间戳而非客户端时间戳，避免客户端通过加快本地时钟作弊提速。

#### 评估移动

服务器使用 `ServerMove` 数据重建玩家控制器的控制旋转，然后调用 `MoveAutonomous` 处理加速度、旋转和跳跃输入。

`MoveAutonomous` 使用上一步得到的 delta time 调用 `PerformMovement`，模拟角色移动物理。服务器不是从客户端移动起点开始模拟，而是从服务器副本在收到 `ServerMove` 时所处的位置开始模拟。

如果角色正在执行动画根运动，`MoveAutonomous` 还会使用传入的 delta time tick 角色动画姿势，动画事件也会正常触发；否则动画按普通方式 tick。

### 处理客户端错误与校正

服务器移动假设服务器与拥有者客户端从同一位置开始，并且执行相同移动后会到达相同位置。如果连接问题导致客户端移动丢失，或客户端提交了错误数据，两者就会到达不同位置，此时必须校正。`ServerMoveHandleClientError` 负责这一处理。

#### 判断是否需要校正

频繁校正会增加带宽，并让客户端反复重模拟大量已保存移动。因此先检查 `WithinUpdateDelayBounds` 的返回值，确认两次移动之间是否已达到最小时间间隔。返回 `false` 时不发送校正；返回 `true` 时继续检查。

接着使用 `ServerCheckClientError` 判断服务器与客户端误差是否足够大。如果返回 `true`，或 `bForceClientUpdate` 被设置为 `true` 强制校正，`ServerMoveHandleClientError` 才继续执行。

相关参数位于 `BaseGame.ini`，项目可在 `DefaultGame.ini` 中覆盖。`ClientErrorUpdateRateLimit` 指定服务器向客户端发送错误校正的最小间隔（秒）；`MAXPOSITIONERRORSQUARED` 是网络游戏中允许而无需校正的最大位置误差平方值。两者位于配置文件的 `[/Script/Engine.GameNetworkManager]` 节。

需要校正时，服务器预测数据会用服务器角色当前状态填充 `FClientAdjustment` 结构 `PendingAdjustment`，包括位置、旋转、速度以及可能作为角色移动基准的物体。无需校正时，则将 `PendingAdjustment.bAckGoodMove` 设为 `true`，表示客户端移动有效。

#### 发送客户端校正或确认移动

向客户端确认移动的最终调用是 `SendClientAdjustment`。它不是 `ServerMove_Implementation` 的一部分，而是服务器 tick 末尾调用的 `UNetDriver::ServerReplicateActors` 的一部分，该函数还负责其他客户端校正 RPC。

如果 `PendingAdjustment.bAckGoodMove` 为 `true`，则调用 `ClientAckGoodMove` RPC，告诉拥有者客户端移动有效。客户端会从 `SavedMoves` 移除原移动，并将其记录为 `LastAckedMove`。如果该标志为 `false`，则调用客户端校正函数发送最终校正数据。

#### 自主代理接收客户端校正

客户端校正 RPC 包括 `ClientAdjustPosition`、`ClientAdjustRotation`，速度为零时使用的缩短版本，以及根运动专用版本。`SendClientAdjustment` 可能根据误差性质和严重程度调用一个或多个函数。每个函数都能在必要校正完成后指示 `ClientPredictionData` ACK 移动，并将 `bUpdatePosition` 设为 `true`。

最终校正在客户端下一次 `TickComponent` 开始时通过 `ClientUpdatePosition` 应用。

## 向模拟代理复制移动

非拥有者客户端上的角色是模拟代理。其复制流程比自主代理简单：模拟代理只需响应服务器。收到服务器移动更新后，它将位置、旋转和速度设置为服务器指定的值，并执行额外处理，让运动更平滑可信。

### 保存复制的移动信息

Actor 复制移动时不会直接复制 Transform，而是维护名为 `ReplicatedMovement` 的复制变量，类型为 `FRepMovement`。

`bReplicateMovement`（Blueprint 中的 Replicate Movement）控制 Actor 是否将移动信息存入该结构并复制给客户端。客户端收到 `ReplicatedMovement` 更新后，RepNotify 函数 `OnRep_ReplicatedMovement` 会解包数据并更新 Actor 的位置和速度。

`ReplicatedMovement` 和其 OnRep 在 Blueprint 中不可访问，但可在 C++ 中重写 `OnRep_ReplicatedMovement`，也可在 `GetLifetimeReplicatedProps` 中重写复制条件，从而定制 C++ Actor 类的移动复制行为。

在 `ACharacter` 中，`ReplicatedMovement` 只复制给模拟代理。自主代理使用服务器移动和客户端校正 RPC 处理移动，因此会忽略该结构。

如果角色以另一个 Actor 为基准，则使用 `ReplicatedBasedMovement`，其中包含确保客户端正确依附服务器基准的额外逻辑。如果使用根运动系统，则这些流程会被忽略，改用 `RepRootMotion`。

### 模拟代理上的移动 Tick

模拟代理执行 `UCharacterMovementComponent::TickComponent` 时，会调用 `SimulatedTick`。它不会重复执行上面的复制移动，而是依据最近收到的复制数据继续移动。普通移动物理会调用 `SimulateMovement`，最后通过 `SmoothClientPosition` 完成验证和网络平滑。

### 执行模拟移动

`SimulateMovement` 负责移动模拟代理；除了由 `SimulatedTick` 调用，也会由 `OnRep_ReplicateMovement` 调用。它会：

- 调用所属角色的 `GetReplicatedMovement` 获取 `ReplicatedMovement`；
- 检查复制数据有效性以及客户端基准是否已解析；
- 检查是否收到网络更新；
- 使用 `GetReplicatedMovementMode` 应用服务器的移动模式；
- 重置所有网络更新标志；
- 根据当前 `MovementMode` 和角色状态执行模拟移动逻辑。

与普通移动物理相比，模拟移动高度简化，大部分逻辑直接位于 `SimulateMovement` 中，而不是拆成多个函数。不过它仍负责更新本地移动状态，包括下一步移动模式、是否已落地以及速度。这些信息用于正确更新动画，并让运动看起来足够准确。

### 网络平滑

如果只复制角色的位置和旋转，角色会每隔一段时间瞬移一次。这是因为本地渲染频率通常高于网络发送频率，例如显示器可能以 240 Hz 渲染，而复制移动每秒只发送 30 次。

网络平滑会将角色从源位置逐步插值到目标位置，而不是立即跳到目标。源位置是角色当前的位置，目标位置来自客户端预测数据。插值由 `SmoothClientPosition` 处理，使用 `NetworkSmoothingMode` 决定具体方式。

## 特殊移动情况

本节介绍常见特殊情况，包括传送、自定义移动以及特殊能力中常见的代码驱动移动。

### 在多人游戏中传送角色

可以调用任意 `SetLocation` 函数或 Blueprint 的 Teleport 节点传送角色，但必须满足：

1. 调用发生在服务器上。
2. 使用 `SetLocation` 函数时，将 `bTeleport` 设为 `true`，使系统识别为传送。

满足条件后，移动会在服务器预测数据和复制移动中记录为传送，所有客户端都会直接将角色吸附到目标位置，而不会进行平滑。

### 使用自定义移动模式

`MOVE_Custom` 会暂停其他移动物理，使你能够实现自定义移动逻辑而不受 `UCharacterMovementComponent` 普通流程干扰。

`UCharacterMovementComponent` 通常不能直接 Blueprint 化，因此 Blueprint 中的自定义移动一般在 Character 内通过 `UpdateCustomMovement` 事件实现。可以使用 Custom Movement Mode 字节变量提供子模式，再通过整数 Switch 或转换为自定义枚举进行分支。

`UpdateCustomMovement` 由组件的 `PhysCustom` 调用。`StartNewPhysics`、`PhysCustom` 以及其他移动物理函数都是虚函数；如果在 C++ 中创建自定义 `UCharacterMovementComponent`，可以直接重写它们。

## 使用根运动复制特殊移动

Gameplay Ability System 创建的能力或动画驱动动作有时需要在短时间内直接控制角色移动。单机中这样做很简单，但网络游戏中的特殊移动必须使用根运动。根运动通常指从动画应用移动，同时也支持代码驱动的特殊移动。

无论组件当前使用哪种移动模式，根运动始终优先于普通移动物理。根运动结束后才恢复普通移动。

### 来自动画蒙太奇

根运动通常来自用于代码触发一次性动画的 `AnimMontage`。使用根运动时，角色会暂停其他移动，改为消耗骨骼根骨骼的位移并转换到世界空间，让动画控制角色移动；动画完成后恢复普通物理。

如果角色处于下落模式，即使正在执行根运动，重力仍会作用于 Z 轴移动。

在前述复制过程中，`FSavedMove_Character` 会捕获根运动信息，包括来源 `AnimMontage`、角色在蒙太奇中的轨道位置以及移动参数本身。

服务器和拥有者客户端上的自主代理不会检查双方是否播放同一动画，因为动画通常属于表现层。因此必须由游戏逻辑保证所有机器正确触发 `AnimMontage`。模拟代理也有与上述流程对应的根运动同步处理。

Gameplay Ability System 插件通过复制触发蒙太奇的能力来同步 `AnimMontage` 和根运动。

### 来自根运动源

有时需要手动控制角色位置，例如让角色跃起指定高度后落到移动目标上。单机游戏可以直接使用 `SetLocation` 和 `SetRotation`，但网络游戏不会在上述复制流程中捕获这种移动，服务器会把客户端最终位置视为错误并发送校正。

动画蒙太奇的根运动只遵循动画预先计算的位移，通常不能实时读取世界信息（例如其他角色的位置），也不容易用游戏变量微调。根运动源允许程序员手动控制根运动，从而在网络环境中利用根运动复制系统，同时以代码控制角色移动。

根运动源应应用到拥有者客户端上的自主代理。

使用该系统时，创建新的 `FRootMotionSource`。不同变体用于不同移动类型，例如 `FRootMotionSource_MoveToForce` 用于从起点直线移动到目标，`FRootMotionSource_JumpForce` 用于跳跃弧线。创建合适的源后，设置起点、目标和移动参数。

`UCharacterMovementComponent::ApplyRootMotionSource` 会将根运动源应用到角色，并返回之后引用它的句柄。根运动源本身不处理移动；角色移动组件会按照 `FRootMotionSource` 参数代替动画执行移动。若该源应用于自主代理，最终会加入 `FSavedMove_Character` 的 `SavedRootMotion`，并纳入复制循环。

移动完成后，必须使用 `ApplyRootMotionSource` 返回的句柄调用 `UCharacterMovementComponent::RemoveRootMotionSource` 将其移除。Gameplay Ability System 包含多个使用根运动源的能力任务，例如可参考 `AbilityTask_ApplyRootMotionMoveToForce`。

## 定制网络角色移动

Unreal Engine 支持复制自定义 Character 移动函数参数。如果不需要该功能并希望保留旧 API，可在项目构建文件中将 `SUPPORT_DEPRECATED_CHARACTER_MOVEMENT_RPCS` 定义为非零值，并将控制台变量 `p.NetUsePackedMovementRPCs` 设为 0。

角色移动组件通过 `FSavedMove_Character` 在网络上传输数据。系统将一次或多次更新的移动数据合并为可变长度 bit 流。把旧数据和新数据打包在一起可以避免 `ServerMoveOld` RPC 在 `ServerMove` 之后到达时产生顺序问题，防止仍然重要的旧数据被错误地当成过期数据丢弃。内部组件使用新的 `CallServerMovePacked`，将多个 `FSavedMove_Character` 序列化到 `FCharacterNetworkMoveDataContainer` 中，取代旧的 `CallServerMove` 用法。

### 扩展已保存移动数据

要添加新数据：

1. 扩展 `FSavedMove_Character`，加入 Character Movement Component 所需信息。
2. 扩展 `FCharacterNetworkMoveData`，加入要发送的数据；多数情况下它与 `FSavedMove_Character` 中新增的数据对应。
3. 扩展 `FCharacterNetworkMoveDataContainer`，使其能够序列化自定义数据并在接收时反序列化。

完成后进行配置：

- 修改自定义角色移动组件，通过 `SetNetworkMoveDataContainer` 使用创建的 `FCharacterNetworkMoveDataContainer` 子类。最简单的做法是在组件子类中添加一个实例，并在构造函数中调用 `SetNetworkMoveDataContainer`。
- `FCharacterNetworkMoveDataContainer` 需要自己的 `FCharacterNetworkMoveData` 实例；通常在构造函数中将它指向自定义 `FCharacterNetworkMoveData` 子类实例，可参考基类构造函数。
- 在扩展的 `FCharacterNetworkMoveData` 中重写 `ClientFillNetworkMoveData`，从已保存移动复制或计算数据；重写 `Serialize`，使用 `FArchive` 读写数据。`FArchive` 即 RPC 所需的 bit 流。
- 若要扩展服务器对客户端的响应（确认有效移动或发送校正），扩展 `FCharacterMoveResponseData` 和 `FCharacterMoveResponseDataContainer`，并重写角色移动组件版本的 `SetMoveResponseDataContainer`。

### 访问扩展移动数据

为保持向后兼容，客户端移动在服务器上的处理，以及客户端收到校正后重放移动的函数调用栈没有改变。这样可以保持旧函数 API 稳定，但函数签名也不会直接包含新的移动数据。

在服务器处理移动时，或客户端收到校正并重放移动时，可以调用 `GetCurrentMoveData`，再将返回的 `FCharacterNetworkMoveData` 转换为自定义子类，以访问扩展数据。
