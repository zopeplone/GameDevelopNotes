# 漫威争锋技能编辑器复刻设计

> 本文回答一个工程问题：如何在 UE 5.8 中复刻截图所示的“技能编辑器”，让策划从一个 Ability 入口完成时间轴、动画、伤害检测、Buff、投射物、召唤物、GameplayCue 和预览调试。
>
> 文中使用四种证据：**截图观察**、**讲座内容**、**FModel 解包字段**、**UE 5.8 源码行为**。解包只能证明序列化出来的资产结构和引用关系，不能证明原游戏的 C++ 算法；凡是实现建议都会明确标注为复刻方案。

## 1. 先说结论

漫威争锋的技能编辑器不应被实现成一个单纯的蒙太奇编辑器，也不应把所有逻辑塞进一个 GameplayAbility 蓝图。它更接近一个以 Ability 为根的资产工作台：

```text
Ability 目录/输入/消耗/CD
        ├── ExtendConfig（英雄或技能族专用参数）
        ├── Timeline（动画片段 + 逻辑事件）
        ├── Scope / Projectile / InstantAmmo / Summoner
        ├── BuffSpec -> EffectTemplate -> GameplayEffect
        ├── GameplayCue / Camera / Hit Feedback
        └── 预览角色、碰撞调试、网络预测模拟
```

它应作为 Marvel 项目内部功能，而不是通用插件。运行时继续使用项目已有 `MarvelAbilityItem`、`AnimTimeline`、Config、AbilityTask 和 ASC；只新增 Editor-only 模块：

```text
Source/
  Marvel/                       # 现有运行时：AbilityItem/AnimTimeline/Config/GAS
  MarvelAbilityEditor/          # Toolkit、Slate、预览、Details Proxy
  MarvelDeveloper/              # 可选：校验、自动化测试、命令行导入
```

不要直接引用 `Engine/Source/Editor/Persona/Private` 中的私有 `SMontageEditor`、`SAnimTimeline`。它们适合阅读和仿照行为，不是稳定 API。项目内部编辑器应使用 `FAssetEditorToolkit`、`FTabManager`、`IDetailsView`、`FPreviewScene`、`FScopedTransaction` 等公开基础设施，并直接编辑 Marvel 的既有资产。

## 3. 截图界面拆解

### 3.1 顶部工具栏

截图顶部有打开技能蓝图、角色/皮肤/预览对象选择、创建 GameplayCue、添加技能派生物和 `Timeline/Graph` 切换。复刻时顶部栏应绑定命令：

| 控件 | 作用 | 数据来源 |
|---|---|---|
| 打开技能蓝图 | 在当前 Ability 的 `GrantedAbility` 上打开 BP | `MarvelAbilityItem.GrantedAbility` |
| 角色/皮肤 | 选择预览 Pawn、骨骼、材质和动画 | Hero/skin 资产引用 |
| 创建 GameplayCue | 新建 Cue 资产并写入 Cue 引用 | Cue 类注册表 |
| 添加技能派生物 | 以模板生成 Ability/ExtendConfig | Ability 模板 |
| Timeline/Graph | 同一资产的时间轴和 GAS 图逻辑视图 | EditorMode 状态 |

### 3.2 左侧配置区

左上是 Cue 浏览器，列出 GameplayTag、皮肤、Cue Blueprint、描述。左下是可切换的 Projectile、Scope、Ability、Buff 等数据编辑器。右下角的 Row Details 采用可折叠分组（Scope Rule、Quote、引用、Prediction 等）。

这些页面应共享一个 `FMarvelAbilityEditorModel`，根对象是 `MarvelAbilityItem`，通过其引用 ID 定位 `AnimTimeline`、`ExtendConfigInline` 和各数据表行；切换标签只改变 Details 对象，不复制数据。对每个引用显示“打开源资产”“在时间轴定位”“反向引用”三个动作。

### 3.3 中央预览与底部时间轴

中央是带角色的预览场景，红色线框显示 Scope/碰撞/Socket/轨迹。底部是典型 Montage 形态：`Sections`、`Montage`、`Timing`、`Notifies` 轨道，带尺、吸附、播放头、播放/暂停/逐帧和当前时间。节点颜色来自 `TrackColor`/`NotifyColor` 或节点类默认颜色；选中节点后右侧 Details 即时更新。

## 4. 与 UE 5.8 Montage Editor 的对应关系

### 4.1 可复用的交互模型

`SMontageEditor::Construct` 创建 `FAnimModel_AnimMontage`，绑定 Montage 改动回调，再交给公共动画编辑器基类构建视图。`FAnimModel_AnimMontage::RefreshTracks` 的顺序是：清理选择、重建根轨道、Montage 面板、Timing 面板、Notify 轨道、曲线轨道、吸附时间、Section 时间，然后广播 `OnTracksChanged` 和更新可视范围。

技能编辑器应一比一复用这套“Model 负责数据，Track 负责时间轴，Widget 负责绘制”的分层，但根轨道改成：

```text
AbilityTimelineRoot
  ├── SectionsTrack
  ├── MontageTrack
  ├── TimingTrack
  ├── LogicNotifyTracks（Tag、Scope、Projectile、Buff、Cue）
  ├── CameraTrack
  └── DebugTrack（可选）
```

### 4.2 必须复刻的修改语义

UE 源码在拖动 Section 时使用 `FScopedTransaction`、`Modify()`、设置时间、`Link()`、排序、刷新 Notify 偏移、`PostEditChange()` 和 `MarkPackageDirty()`。技能节点拖动、调整持续时间、替换节点、改轨道名都必须遵循相同语义：

1. 开始交互创建一个事务；
2. 所有受影响的 UObject/Outer 都 `Modify()`；
3. 以秒为权威时间，必要时换算帧；
4. 重算 Section/Notify 的链接和边界；
5. `PostEditChange`，广播模型变更；
6. 标记包脏，保证 Ctrl+Z 和保存可用。

`UAnimMontage::RefreshBranchingPointMarkers()`、`SortNotifies()` 和 Notify trigger offset 刷新表明：运行时缓存不能只在编辑器修改时更新，加载、导入、网络复制和长度变化也要重建。

### 4.3 不应照搬的部分

UE Montage 的 Notify 主要面向动画回调；Marvel `AnimTimeline` 的节点直接驱动检测、生成、Buff 和预测窗口。复刻时应保留项目现有的 `AnimNotify_SpawnScope`、`AnimNotify_ApplyBuff` 等节点体系及其运行时调度，不应再定义一套平行的通用 Timeline 节点并转换数据。

## 5. 运行时数据模型

### 5.1 根资产：直接使用 `MarvelAbilityItem`

```cpp
UCLASS(BlueprintType)
class UMarvelAbilityItem : public UObject // 以项目真实声明为准
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere) TSoftClassPtr<UGameplayAbility> GrantedAbility;
    UPROPERTY(EditAnywhere) TObjectPtr<UAnimTimeline> TimelineToPlayMontage;
    UPROPERTY(EditAnywhere, Instanced) TObjectPtr<UMarvelAbilityConfig> ExtendConfigInline;
    UPROPERTY(EditAnywhere) TArray<FMarvelAbilityBindInputConfig> BindInputConfigs;
    UPROPERTY(EditAnywhere) TArray<FMarvelCostAttrAction> CostAttrActions;
    UPROPERTY(EditAnywhere) TArray<FGameplayTag> AbilityGameplayCues;
};
```

`MarvelAbilityItem` 是此根资产的参考：它把 `GrantedAbility`、`ExtendConfigInline`、`TimelineToPlayMontage`、输入绑定、Cost、Ready/Commit 阶段、Combo、Camera、HitFeedback 和 Cue 集合组装在一起。

### 5.2 直接编辑现有 `AnimTimeline` 与事件

```cpp
USTRUCT(BlueprintType)
struct FMarvelAnimTimelineEventView // 编辑器视图，底层字段以现有结构为准
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere) FName NotifyName;
    UPROPERTY(EditAnywhere) float StartTime = 0.f;
    UPROPERTY(EditAnywhere) float Duration = 0.f;
    UPROPERTY(EditAnywhere) float TriggerTimeOffset = 0.f;
    UPROPERTY(EditAnywhere) float EndTriggerTimeOffset = 0.f;
    UPROPERTY(EditAnywhere) int32 TrackIndex = 0;
    UPROPERTY(EditAnywhere) FLinearColor NotifyColor;
    UPROPERTY(EditAnywhere) TObjectPtr<UObject> NotifyObject;
    UPROPERTY(EditAnywhere) TSubclassOf<UObject> NotifyStateClass;
    UPROPERTY(EditAnywhere) FGuid Identity;
};

USTRUCT(BlueprintType)
struct FMarvelAnimTimelineTrackView
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere) FName TrackName;
    UPROPERTY(EditAnywhere) FLinearColor TrackColor;
    UPROPERTY(EditAnywhere) TArray<FMarvelAnimTimelineEventView> Events;
};

UCLASS(BlueprintType)
class UAnimTimeline : public UObject // 使用项目既有类型，不重新声明资产
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere) float SequenceLength = 0.f;
    UPROPERTY(EditAnywhere) TSoftObjectPtr<UAnimMontage> Montage;
    UPROPERTY(EditAnywhere) TArray<FMarvelAnimSection> AnimSections;
    UPROPERTY(EditAnywhere) TArray<FMarvelAnimNotifyTrack> AnimNotifyTracks;
    UPROPERTY(EditAnywhere) bool bFastTickOnActive = false;
    UPROPERTY(EditAnywhere) bool bStopAutomatically = true;
};
```

解包中 `NotifyObject` 指向 `AnimNotify_SpawnScope` 等内嵌 UObject，`NotifyStateClass` 承载状态节点。编辑器必须遵循项目当前序列化形态、Outer 与版本字段；不应为了“更通用”改成 `FInstancedStruct`，否则会与现有数据、热更和运行时加载链不兼容。

### 5.3 Section

Section 至少包含 `SectionName`、`NextSectionName`、`Time`、循环/结束策略。编辑器拖动 Section 后按时间排序，并重新计算所有事件的有效区间。运行时用 Section 名称而不是数组下标跳转，避免策划排序后引用失效。

### 5.4 节点 Payload 分层

通用层只放调度所需字段：时间、持续时间、类、颜色、Identity。业务层由节点 Payload 提供：

| 节点 | Payload 建议 |
|---|---|
| TagNotify/Begin/End | `FGameplayTag`、是否触发 Ability 阶段 |
| ApplyBuff/RemoveBuff | BuffSpec ID、目标策略、SetByCaller 数值 |
| SpawnScope | Scope ID、Socket、位置/旋转偏移、预测策略 |
| SpawnProjectile | Projectile ID、发射 Socket、初速度、目标模式 |
| SpawnSummoner | Summoner ID、数量、持续时间、Owner |
| CameraShake/CameraInterp | Camera 资产、强度、混合/恢复曲线 |
| TimedOwnedTags/TimedBlockTags | Tags、持续时间、堆叠策略 |
| AbilitySocketInfo | Socket 名、附着规则、网络复制规则 |

节点注册表返回显示名、颜色、可编辑 Payload、校验器、预览绘制器和运行时执行器。这样增加英雄专用节点只需新增类和注册，不改时间轴核心。

## 6. Timeline 运行时执行器

### 6.1 时间推进

项目已有 `AnimTimeline` 播放器/AbilityTask 应维护 `CurrentTime`、`LastTime`、播放方向、Section、循环次数和已进入的 NotifyState。若复刻项目尚缺该运行类，应围绕 `UAnimTimeline` 补齐，而不是创建另一套 Timeline 数据体系。每帧执行：

```text
NewTime = min(CurrentTime + DeltaSeconds * Rate, SequenceLength)
处理 (LastTime, NewTime] 内的瞬时事件
对跨越区间的 NotifyState 调用 Begin/Tick/End
遇到 Section 边界，按 NextSectionName 跳转或结束
CurrentTime = NewTime
```

必须处理 DeltaTime 过大、暂停后恢复、时间跳转和倒放。一次 Tick 跨过多个事件时按时间排序全部补发，不能只检查 `Event.StartTime == CurrentTime`。

### 6.2 触发偏移与状态

瞬时事件的有效触发点为 `StartTime + TriggerTimeOffset`。状态事件的 Begin/End 分别应用开始和结束偏移；负偏移要在资产校验阶段限制在 `[0, SequenceLength]`。事件 Identity 用于网络重放、撤销和避免同一事件重复执行。

### 6.3 取消、死亡和回滚

Ability 取消、Owner 死亡、Montage 中断时，播放器必须遍历活动状态并调用 End/Cleanup：移除 OwnedTag、停止 CameraInterp、销毁 Scope/Projectile、撤销预测 Cue。服务器拒绝预测激活时，客户端按事件日志逆序回滚，再接受服务器快照。伤害、目标控制、变身等不可安全回滚的效果只在服务器提交；移动、输入反馈、自己的资源消耗和技能激活可以预测，具体边界遵循讲座中的“是否影响手感/是否可恢复”标准。

### 6.4 GAS 对接

`UGameplayAbility` 负责权限、Cost、Cooldown、Commit 和取消；项目 `AnimTimeline` 播放器是 AbilityTask 或 Ability 内部的执行组件。推荐：

1. Ability 激活时创建 PredictionKey 和 Timeline Player；
2. 播放动画 Montage，Timeline 以同一时钟驱动逻辑 Notify；
3. Notify 执行 Scope/Projectile/Buff 等服务；
4. 服务端验证关键输入和命中结果；
5. Cue 通过 GameplayCueManager/TypedCue 表现，避免节点直接操作 Niagara。

## 7. 编辑器模块架构

### 7.1 Toolkit 与编辑器模式

```cpp
class FMarvelAbilityEditorToolkit : public FAssetEditorToolkit
{
    TSharedPtr<FMarvelAbilityEditorModel> Model;
    TSharedPtr<IDetailsView> Details;
    TSharedPtr<SMarvelAnimTimeline> Timeline;
    TSharedPtr<ISequencer> OptionalSequencer; // 仅在需要时桥接
    TSharedPtr<FMarvelAbilityPreviewClient> Preview;
};
```

`FMarvelAbilityEditorModel` 持有当前 `MarvelAbilityItem`、解析出的 `AnimTimeline`、选择集、视图范围、吸附时间和 Config/表行弱引用；Track Widget 不直接改 UObject。为 `MarvelAbilityItem` 注册/扩展 `UAssetDefinition`，使用 `FUICommandList` 提供保存、复制、粘贴、对齐、删除、预览等命令。

### 7.2 Tab 与布局

建议 Tab：

```text
Toolbar
 ├─ Cue Browser / Related Assets（左上）
 ├─ Linked Data Details（左下）
 ├─ Preview Viewport（中央上）
 ├─ Timeline（中央下）
 └─ Node Details + Sections（右侧）
```

使用 `FTabManager` 和 `SSplitter`，保存布局到 `EditorPerProjectUserSettings`。窗口重开后恢复当前 Ability、选中节点和时间。

### 7.3 时间轴 Model

Model API 应至少包括：

```cpp
void RefreshTracks();
void SetScrubPosition(double Time, bool bDragging);
void AddEvent(FName Track, FMarvelAnimTimelineEventView Event);
void MoveSelection(double DeltaTime, bool bSnap);
void ResizeSelection(double NewDuration);
void DeleteSelection();
void CopySelection(FString& OutText) const;
bool PasteSelection(const FString& Text, double AtTime);
TArray<double> GetSnapTimes() const;
```

吸附点包括 Section 时间、事件开始/结束、Montage 标记、帧边界和可选的自定义 Gameplay Tag。视图范围分离为 ClampRange（资产边界）与 ViewRange（当前缩放），支持框选、滚轮缩放、Outliner 搜索和逐帧输入。

### 7.4 Track/Node Widget

轨道左侧显示名称、颜色、锁定、可见和折叠状态；右侧绘制节点。瞬时节点用菱形或箭头，State 节点用可调整宽度的条。鼠标操作必须区分点击选择、拖动、调整左右边界、框选和时间轴平移。节点右键菜单提供复制、替换 Notify 类、移动到轨道、在预览时刻播放和打开关联资产。

### 7.5 Details 与关联编辑

Details 不能直接显示匿名数组元素，否则选中节点后无法稳定编辑。为事件建立 `UMarvelAnimTimelineEventProxy : UObject`，代理属性映射到现有 `AnimTimeline/Track/Event/NotifyObject`，并实现 `PostEditChangeProperty` 将修改写回原对象。Ability、Buff、Scope 等使用项目表行 Proxy，显示 ID、源资产路径、引用者和校验错误。

## 8. 预览场景与调试

### 8.1 预览沙箱

`FMarvelAbilityPreviewClient` 基于 `FPreviewScene` 或独立 Editor World 创建 Pawn、SkeletalMesh、ASC、AttributeSet、Ability 授予和 `AnimTimeline` 播放对象。预览世界不得使用真实比赛 GameState；所有伤害、Buff 和召唤物都进入可重置的 Sandbox。提供“只表现”“本地 GAS”“服务器/客户端双实例”三种模式。

### 8.2 调试绘制

Scope、Projectile、Socket、Trace、命中结果用独立 Debug Drawer 绘制：颜色来自节点颜色，线框/箭头/半透明区域可切换。播放头移动时同步计算瞬时位置；暂停状态仍允许拖动时间预览。对于相机节点，使用 Preview Camera Blend 而不是修改编辑器主视口相机。

### 8.3 预览控制

必须有播放、暂停、停止、逐帧、跳到 Section、循环、播放全部 Sections、速率和自动停止。截图右侧的 Sections 面板对应 `Create Default`、`Clear`、`Preview All` 和单个 Section 预览命令。

## 9. 关联配置页面如何组织

### 9.1 Ability

编辑 `MarvelAbilityItem` 等价字段：GrantedAbility、输入绑定、激活条件、CostAttrActions、ReadyCostStage、CommitCooldownStage、Combo、循环和失败反馈。Ability BP 的 Instanced Tags、网络策略、阶段取消扩展仍保留在 BP Details；编辑器只提供快捷入口和引用校验。

### 9.2 Scope/Projectile/InstantAmmo

Scope 页面编辑形状、半径/长度、Anchor、起终点、Trace 模式、目标 Tag、遮挡、传送门、检测频率、命中次数、Cost、预测和结果 Buff。Projectile 页面编辑 Actor、碰撞、速度、重力、追踪、弹跳、穿透、命中 Buff、RPC/更新频率和可见性。InstantAmmo 页面编辑瞬时枪线、穿透、命中次数、伤害和服务器校验。

### 9.3 Buff/Effect

Buff 页面分三层：

1. `MarvelEffectTemplate`：状态身份、Duration/Period、Asset/Target Tag、免疫、移除、授予 Ability、Cue、韧性。
2. `GameplayEffect` 蓝图：UE 5.8 的 `AssetTagsGameplayEffectComponent`、`TargetTagsGameplayEffectComponent`、`AbilitiesGameplayEffectComponent`、Block/Cancel、AdditionalEffects 等运行载体。
3. `FMarvelBuffSpec`：某个技能本次实例的 EffectID、AttributeValue/Diffusion、持续时间、Period、叠层、SetByCaller、目标和预测覆盖。

编辑器应在同一 Details 中显示三层来源，并在修改时明确“改模板会影响多个技能”“改 Spec 只影响当前技能”。

### 9.4 Cue、Camera、Equipment、Summoner

Cue 浏览器按 GameplayTag、Cue Blueprint、皮肤和描述过滤；Cue 资产提供动画/FX/UI/ScreenFX 引用和参数。Camera 页面编辑 CameraInterp、Shake、曲线和恢复。Equipment 页面关联 Weapon Actor、AmmoSpec 和 ShootingLogic。Summoner 页面编辑 Actor、ASC、初始属性/状态、数量、阵营、生命周期、能量、可见性和网络规则。

## 10. 配置与代码的边界

### 10.1 适合配置的内容

- ID、GameplayTag、资产软引用和输入映射；
- Montage、SequenceLength、Section、Notify 时间、颜色和轨道；
- Scope/Projectile/Summoner 的几何、速度、数量、生命周期、目标过滤；
- Buff 的数值、Duration、Period、叠层、Tag、Cue 和 SetByCaller；

### 10.2 必须硬写代码的内容

- ASC 初始化、Ability 授予/移除、权限和 PredictionKey；
- Timeline 跨帧调度、Seek、Loop、Section 跳转、NotifyState 生命周期；
- Trace/碰撞、目标过滤、穿透/弹跳、命中去重；
- Spawn/Destroy、Projectile 移动、Summoner 行为和服务器校验；
- GAS GameplayEffectSpec、SetByCaller、Attribute 聚合和回滚；
- TypedCue 到 Niagara/音频/UI 的参数桥接；

判定规则：若改字段只改变“同一种行为的参数”，配置；若需要新的时序、碰撞、网络或状态语义，写节点执行器/AbilityTask/C++。

## 12. 从零实现路线

### 阶段一：数据与预览垂直切片

实现根资产、Timeline、一个 `TagNotify` 和一个 Montage；预览 Pawn 能播放，时间轴能拖动，节点能选中和显示 Details。

### 阶段二：编辑器基本功

加入多轨道、Section、State 节点、吸附、框选、复制/粘贴、替换类、事务、Undo/Redo、保存和脏包。

### 阶段三：战斗原语

实现 SpawnScope、SpawnProjectile、ApplyBuff、RemoveBuff、TimedOwnedTags、CameraShake，并在预览中绘制 Scope 和命中结果。

### 阶段四：GAS 与网络

接入 ASC、Cost/Cooldown、GameplayEffect、Cue、客户端预测窗口、服务器校验和拒绝回滚；增加双实例网络预览。

### 阶段五：关联资产工作台

完成 Ability/Buff/Scope/Projectile/Summoner/Equipment/Cue 标签页、反向引用、模板派生、依赖追踪、批量校验和 Cook 前报告。

## 13. 校验与验收标准

### 13.1 数据校验

- `SequenceLength > 0`，所有事件位于有效边界；
- State 节点 `Duration > 0`，开始时间小于结束时间；
- TrackIndex、Section 名称、Identity 唯一；
- Montage 长度、Timeline 长度和动画播放速率关系明确；
- 所有软引用可加载，Ability/Buff/Scope/Projectile/Summoner ID 存在；
- EffectTemplate 的 DurationPolicy、GE Component 和 BuffSpec 不矛盾；
- 预测节点不能直接修改服务器权威血量或控制状态；
- Cue、Camera、Socket、GameplayTag 均有有效资产或降级策略。

### 13.2 编辑器验收

- 拖动节点、改时间、改持续时间、改轨道名都可撤销；
- 修改后 Details、预览、时间轴和引用页面即时同步；
- 重开编辑器恢复布局和选中状态；
- 播放跨越多个事件时每个事件只执行一次；
- 停止、取消、死亡和跳转都会清理活动 State；
- 预览 Scope/Projectile/Camera/Cue 与运行时路径一致；
- 资产重命名、删除和重定向有错误提示，不产生静默空引用。

### 13.3 自动化测试

至少覆盖：Timeline 排序、跨帧触发、倒放、循环、Section 跳转、NotifyState Begin/End、取消清理、预测拒绝回滚、Buff 叠层、Projectile 穿透去重、软引用加载和 Cook 校验。

## 14. 常见错误

1. 把 Timeline 当成动画曲线，只在 Montage Notify 回调里做逻辑，导致跳帧和网络重放不一致。
2. 直接复制 Persona 私有 Slate 类，升级 UE 后编译和行为都不可控。
3. 让节点直接 `SpawnActor`、改血量、播 Niagara，绕过 GAS 和服务器权威。
4. 只保存 `NotifyName` 字符串，不保存类路径、Payload 版本和 Identity，导致重命名后数据失效。
5. 时间修改没有 `FScopedTransaction/Modify/PostEditChange/MarkPackageDirty`，用户看到能拖动但无法撤销或保存。
6. 把模板、BuffSpec 和 GameplayEffect 混成一层，策划改一个控制状态时误伤所有英雄。
7. 预览直接使用真实 World/ASC，造成编辑器污染、网络状态泄漏和不可重复的调试结果。

## 16. 最终建议

第一版不要追求完整复制所有英雄专用节点。先完成“一个 Ability + 一个 Montage + Timeline + Scope + Buff + Cue + 预览 + 撤销”的闭环，再以注册表方式增加 Projectile、Summoner、Camera 和英雄扩展。编辑器的价值在于把这些引用和时序放到一个可观察、可校验、可回滚的工作流中；运行时的可靠性则来自 GAS 权威、明确的 Timeline 时钟和每个节点可测试的执行器。
