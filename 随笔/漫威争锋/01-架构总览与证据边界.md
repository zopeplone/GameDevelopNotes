# 01 架构总览与证据边界

## 1. 为什么需要在 GAS 之上再分层

UE GAS 提供四类底座：

| UE 概念 | 基础职责 | 《漫威争锋》资产中的扩展 |
|---|---|---|
| GameplayAbility | 激活、执行、结束、标签关系、网络策略 | AbilityTable、MarvelAbilityItem、技能模板、ExtendConfigInline、Timeline |
| AbilityTask | Ability 内的异步行为 | Timeline 驱动、检测、弹道、位移、召唤等业务 Task |
| GameplayEffect | 属性、Tag、持续时间、叠层、免疫、Cue | `Effect_NNNN` 模板 + BuffSpec 实例 + CDR 细粒度限制 |
| GameplayCue | 表现事件分发 | Cue 资产、CueOptTable、TypedCue、Niagara Data Interface |

GAS 解决的是运行时协议，不会替项目决定数据资产如何组织。几十个英雄、上千个技能条目、模式覆盖和网络预测同时存在时，必须在 GAS 上增加配置层与管线层。

## 2. 当前解包的目录事实

### 2.1 AbilitySystem

`AbilitySystem` 根目录由以下区域组成：

- `1011` 至 `1065`：英雄私有技能资产。
- `Common`：通用 Ability、通用 Effect、通用表、冲量、交互与 QA 资产。
- `Cue`：通用和关卡 Cue。
- `GameMode`、`Level/GameMode`：玩法专用技能、表和覆盖资产。
- `Activity`：活动配置。
- `Debug`：AbilitySystem 调试工具资产。
- `2000`、`4016`、`4018`、`4019`、`9999`：关卡/训练/机器人等非标准英雄实体。

常见文件数量：

| 资产形态 | 数量 | 含义 |
|---|---:|---|
| 数字命名的 AbilityItem JSON | 1,116 | 一个技能的资产入口与通用配置 |
| `Ability_*_BP` | 1,147 | GameplayAbility 或其业务子类蓝图 |
| `Timeline*` | 1,228 | 技能逻辑时序资产 |
| AbilityTable | 125 | 技能注册、UI、CD、统计入口 |
| BuffSpecTable | 157 | Buff 业务实例表；基础英雄表当前为空，模式表存在数据 |
| ScopeAgentTable | 139 | 检测源配置 |
| ProjectileAgentTable | 109 | 延迟弹道配置 |
| SummonerAgentTable | 93 | 召唤物配置 |
| EquipmentTable | 71 | 武器/装备配置 |
| InstantAmmoTable | 68 | 瞬时弹道配置 |
| FlyConfigTable | 73 | 飞行状态配置 |
| CueOptTable | 45 | Cue 优化策略 |
| `Common/GameEffect/Effect_*` | 211 | 可复用 GameplayEffect 模板；`Common/QA` 另有 1 个测试 Effect |

### 2.2 Data

`Data` 不是 UI 杂项，而是 AbilitySystem 的外围入口：

- `MarvelHeroTable`：英雄注册。
- `MarvelHeroBaseAttributeTable`：基础移动、生命、护盾、形态标签。
- `HeroInputMappingContextTable` 与 `Input/AbilityInputData`：Enhanced Input 到技能输入的映射。
- `UI/HeroAbilityUITable` 与各英雄 UIAsset 表：技能图标、说明和展示顺序。
- `GameMode/*/HeroTable`、`MarvelHeroBaseAttributeTable`：玩法级英雄覆盖。
- `*EffectTable`、`*EquipTable`：玩法效果器和装备对战斗数据的覆盖。
- StringTable：本地化文本。FModel 中部分 `LocalizedString` 为空，不能据此判定游戏里没有名称。

## 3. 三态技能配置如何落到资产

讲座把技能配置分成 AbilitySet、AbilityConfig、AbilityPriority。解包并没有一个统一名为 `AbilitySet` 或 `AbilityPriority` 的文件，但职责可以在实际资产中定位。

### 3.1 AbilitySet：稳定、可枚举的通用层

对应：

- AbilityTable 行：ID、输入、CD、UI、统计、DamageType、AbilityAsset。
- MarvelAbilityItem：相机、Timeline 映射、输入绑定、资源消耗、通用激活数据。
- Data/UI：图标、说明、展示顺序。

这层应由稳定结构承载，因为字段需要被编辑器、加载器、UI、统计和网络系统共同读取。

### 3.2 AbilityConfig：技能独有层

对应 `MarvelAbilityItem` 内的 `ExtendConfigInline`。奇异博士传送门 `101861.json` 中，内联对象类型为 `Config_101861`，包含：

- 传送门追踪半径、碰撞通道、盒体尺寸；
- 预放置 Actor 与相机 Actor 类；
- 相机平移、插值和速度档；
- 穿透检查标签；
- 技能持续时间。

全量数字 AbilityItem 中至少出现 157 种 `Config_*` 类型。这证明特殊参数不是塞进统一大结构，而是通过技能私有 UStruct/UObject 类型扩展。

### 3.3 AbilityPriority：关系与抢占层

当前解包中可直接看到：

- Ability 蓝图的 `CancelAbilitiesWithTag`、`BlockAbilitiesWithTag`；
- `ActivationRequiredTags`、`ActivationBlockedTags`、`ActivationOwnedTags`；
- `ActivatePriorityType`、`Priority`、`KeyConsumptionPriority`；
- `CancelAllowedPolicy`、阶段化取消配置等 Marvel 扩展字段。

未发现可确认是全局 AbilityPriority 数据资产的独立导出。因此应写成：**关系层真实存在，但当前证据只证明它部分固化在 Ability CDO 和 AbilityItem 中**。不要擅自假定所有关系都来自一张表。

## 4. 一个技能的完整引用链

以奇异博士传送门 `101861` 为例：

```text
1018_AbilityTable.Rows[101861]
  -> AbilityAsset: MarvelAbilityItem /1018/101861/101861
     -> GrantedAbility: Ability_101861_BP_C
     -> ExtendConfigInline: Config_101861
     -> TimelineToPlayMontage:
          Timeline_101861_Start -> AnimResIndex 0
          Timeline_101861_Open  -> AnimResIndex 1
     -> BindInputs: PlaceActor / EndAbility / Rise / ...

Ability_101861_BP_C
  -> SuperStruct: /Script/Hero_1018.Ability_101861
  -> AbilityTags: Ability.ID.101861, Ability.Type.Status.Main
  -> CancelAbilitiesWithTag / BlockAbilitiesWithTag
  -> ActivationOwnedTags
  -> ReplicationPolicy: ReplicateYes
```

这条链说明：

1. 表负责发现和索引技能。
2. AbilityItem 负责策划可编辑的通用组合。
3. GameplayAbility 类负责执行协议和网络生命周期。
4. ExtendConfigInline 负责不可通用化的英雄机制。
5. Timeline 负责阶段和关键帧，Montage 负责骨骼动画。

## 5. 数据加载与覆盖顺序

根据目录、`TableMerge`、模式表和讲座“效果器”描述，可以建立以下高可信模型：

```text
Common 基础表
  + 英雄基础表
  + 地图/关卡表
  + GameMode 表合并或重定向
  + 活动/装备/天赋效果器
  = 当前对局的只读战斗数据视图
```

配置建议：

- 原始行保持不可变，运行时生成合并后的视图。
- 所有覆盖记录来源、优先级和旧值/新值。
- Ability、Buff、Projectile 等访问都必须经过同一个数据访问层，否则效果器无法“接管所有数据访问”。
- 覆盖粒度以字段路径为单位，不复制整个技能资产。
- 相同优先级的冲突在构建期报错，不依赖加载顺序碰运气。

## 6. 证据边界

### 6.1 能确认的内容

- 资产类型、字段名、引用关系、类继承、Tag、数值和目录分层。
- UE GAS 对 Ability、Effect、Task、Cue、PredictionKey 的公开运行时契约。
- 讲座明确描述的 Marvel 架构目标。

### 6.2 不能确认的内容

- Marvel 私有 C++ 的精确函数实现和执行顺序。
- FModel 未导出的 DataRegistry、运行时热更或服务端数据。
- 蓝图节点被 Cook 后丢失的编辑器语义。
- 当前基础英雄 BuffSpecTable 全部为空的确切原因。模式 Buff 表非空，可能意味着基础数据来自未导出源、运行时合并或该版本做了拆包；文档不会把“空表”解释成“英雄没有 Buff”。

### 6.3 UE 源码快照限制

工作区中的 GameplayAbilities 插件包含完整公开头文件和少量 Private 文件，但核心 `.cpp` 未随该引擎快照保留。因此源码解释以类型声明、注释、属性约束和公开协议为主，不伪造函数内部实现。
