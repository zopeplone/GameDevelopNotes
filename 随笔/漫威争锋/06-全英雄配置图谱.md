# 06 全英雄配置图谱

## 1. 图谱用途

本章不是英雄攻略，而是资产审计入口。表中的角色、定位、攻击方式、形态数来自：

- `Data/DataTable/MarvelHeroTable.json`
- `Data/DataTable/MarvelHeroBaseAttributeTable.json`

Ability 行数和 Timeline 数来自各英雄 `AbilitySystem/<HeroID>` 目录。内部 Ability、被动、换弹、近战、联携、形态辅助技能都计入，所以行数不等于玩家 UI 上的按钮数。

## 3. 每个英雄都要配置的资产包

```text
AbilitySystem/<HeroID>/
  <HeroID>_Table/
    AbilityTable
    BuffSpecTable
    ProjectileAgentTable
    InstantAmmoTable
    ScopeAgentTable
    SummonerAgentTable
    EquipmentTable
    FlyConfigTable
    CueOptTable
  <AbilityID>/
    <AbilityID>.json                 # MarvelAbilityItem
    Ability_<AbilityID>_BP.json      # GameplayAbility
    Timeline_*.json
    Camera / Curve / Projectile / Summon / BuffAbility ...
```

此外在 `Data` 配置：

- MarvelHeroTable：HeroTag、Role、CharacterClass、通用移动/跳跃 AbilityID。
- MarvelHeroBaseAttributeTable：形态 Tag、TurnSpeed、MoveSpeed、Health/Shield/Armor。
- HeroInputMappingContextTable：输入上下文。
- HeroAbilityUITable/UIAsset：UI。
- StringTable：本地化。
- GameMode 表：玩法覆盖。

## 5. 训练与模式角色

- 4016、4018：训练机器人，分别为 Support/Tank；用最小 Ability 集验证通用输入、伤害和检测。
- 4019：奥创机器人；应审计 NPC/召唤物 ASC 的复制简化。
- 9999：HeroZero；通用开发/测试角色，不应被生产 UI 或匹配表误注册。
- 2000：目录包含大量传送门、召唤和通用关卡 AbilityItem，但不在 MarvelHeroTable 标准英雄行中，应按 Level Entity 处理。
- 1071：当前目录只有一份表数据且英雄主表无对应标准行，不能按完整英雄推断。

## 6. 新英雄接入清单

1. 在 HeroTable 注册 HeroID、HeroTag、Role、CharacterClass、通用移动/跳跃 Ability。
2. 在 BaseAttributeTable 为每个形态建立唯一 TypeTag 和完整属性。
3. 创建英雄 Table 包，未使用的表也保留空表以支持统一合并器。
4. 为每个玩家可见技能建立 AbilityTable 行、AbilityItem、GrantedAbility、Timeline 和 UIAsset。
5. 内部技能使用 Passive/OnlyInitialize/Max_None 等语义输入，避免进入普通按键 UI。
6. 优先复用 Effect、Scope、Projectile、Summon 模板；只为独有机制新增 InlineConfig 或组件。
7. 定义 AbilityTag 关系、CD/Cost、输入消费优先级。
8. 接入玩法表合并、联携技能和模式禁用规则。
9. 完成预测副作用表和 200 ms 网络测试。
10. 运行 ID、引用、Tag、Buff 链、Timeline、Cue、模式覆盖校验。
