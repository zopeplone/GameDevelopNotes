# 惩罚者（1014）AbilitySystem 配置详解

> 数据来源：`D:\FModel\Output\Exports\Marvel\Content\Marvel` 的 1014 解包目录；源码依据：`E:\UEProject\UE_5.8\Engine\Plugins\Runtime\GameplayAbilities\Source\GameplayAbilities`。本文只把 JSON 中可复核的值写成“已确认”，把蓝图图表、公共表合并和运行时逻辑标为“待验证”。

## 1. 先建立正确的配置模型

惩罚者不是“一个 Ability 配一个伤害数字”。一项技能至少由下列层次组成：

```text
MarvelHeroTable / BaseAttribute
        |
        +-- AbilityTable(AbilityID、输入、CD、UI、EquipID)
        |       |
        |       +-- Ability_<ID>_BP (GAS GameplayAbility CDO/自定义阶段)
        |       +-- Timeline / AnimNotify (动画时序)
        |       +-- Equipment -> Weapon -> Ammo/Projectile
        |       +-- ScopeAgent / SummonerAgent
        |       +-- BuffSpec / GameplayEffect / GameplayCue
        |
        +-- 服务器验证、PredictionKey、Cue 复制
```

UE 5.8 的 `UGameplayAbility` 将 `AbilityTags`、激活所需/阻断/拥有标签、取消/阻断标签和 Cost/Cooldown GE 作为 CDO 字段；`UAbilitySystemComponent::GiveAbility` 与 `TryActivateAbility` 负责授予和激活，`CommitAbility` 负责消耗资源和进入冷却。因此本英雄的 DataTable 负责“选择和参数”，Blueprint 负责阶段编排，运行时 ASC 负责状态一致性。

证据等级：A=解包 JSON 直接值；B=资产引用可闭包推导；C=需要打开蓝图图表或运行时验证。不要把 C 级推测写成固定数值。

## 4. AbilityItem 字段：从表到 GAS

### 4.1 通用字段

- `GrantedAbility`：引用 `Ability_<ID>_BP`；应先加载 CDO，再由 ASC `GiveAbility` 授予。101402、101451、101461、101481、101482、101483、101492 明确有该引用。
- `ActivateInput`：DataTable 输入映射，如 `WeaponReload`、`Ability1/2`、`Ultimate`、`PrimaryAttack`、`MeleeAttack`。
- `TimelineToPlayMontage`：`Timeline` + `AnimResIndex` 数组。索引将当前武器/阶段映射到具体 AnimMontage。
- `ReadyCostStage` / `CommitCooldownStage`：`None`、`Active`、`Custom` 等 Marvel 阶段；最终仍应在 Ability 的 Commit 点调用 GAS Cost/Cooldown。
- `CostAttrActions`：自定义属性/弹药动作。解析不到具体数组时只能记录“字段存在”。
- `AbilityGameplayCues`：Ability 级 Cue；与 GE 的持续 Cue、Scope 命中 Cue 分开处理。

### 4.2 CDO 中的标签与策略

1014 CDO 使用的字段集合包括 `AbilityTags`、`ActivationOwnedTags`、`ActivationRequiredTags`、`ActivationRequiredAnyTags`、`ActivationBlockedTags`、`CancelAbilitiesWithTag`、`BlockAbilitiesWithTag`、`ReplicationPolicy`、`NetExecutionPolicy`、`bIsCancelable` 和自定义 `IsLoopAbility`。

UE 源码对应关系：`GameplayAbility.h` 475-476 定义 AbilityTags；747/751/755 分别是 Owned/Required/Blocked；739/743 是 Cancel/Block；689-715 是 Instancing/Replication/NetExecution 策略。配置原则是：

1. 武器开火只允许在对应 `Weapon.ID.*` OwnedTag 下执行，换枪时由 101401 取消旧标签能力。
2. 持续技能（101431、101441、101462、101482、101491）将 `IsLoopAbility` 与取消条件配对，释放输入时进入 `EndAbility`。
3. 101411 `ServerInitiated + ReplicateYes`，101421 `ServerOnly`，101483 `ServerInitiated`；这些被动/衍生能力不应依赖本地预测结果。
4. 激活前先用 Required/Blocked 标签做门禁；资源消耗失败时不要播放已提交的 Montage。

## 5. 逐技能配置

### 101401 武器切换

`Config_103`，无单独 `GrantedAbility`，但目录含 `Ability_101401_BP`。四个动画：`Rifle2Shotgun`、`Rifle2Shotgun_Sliding`、`Shotgun2Rifle`、`Shotgun2Rifle_Sliding`，结尾均 `CameraShake_101401_End`。应在切换时更新 Equipment OwnedTags：步枪 `Weapon.ID.01` 与霰弹 `Weapon.ID.02` 互斥，并取消旧武器持续 Ability。UE 的 `CancelAbilitiesWithTag/BlockAbilitiesWithTag` 正是用于防止切换期间并发开火。

### 101402 / 101403 换弹

101402 仅引用 `Ability_101402_BP`。101403 输入 `WeaponReload`，Timeline 三项：`Timeline_101403_Rifle`、`...Shotgun`、`...Shotgun_02`；Shotgun_02 长度 `2.0s`，Montage 为 `101449_ShotgunReloadAll_MT`。`AnimNotify_TagNotify` 发 `Ability.Event.101403.CheckReload`，可作为检查弹匣/取消换弹的事件边界。换弹消耗应在 Ready/Custom 阶段提交，避免预测时重复扣弹。

### 101411 生命阈值透视

Item 的 `HealthStatusLower`、`HealthStatusParam`、`ScopeID=10141101`、`BuffID=10141101`。Scope 是半径 `3000`、周期 `0.1s`、Multi_Overlap、敌方 `Template_02`，本身 BaseDamage=0。应通过 Health 属性监听决定是否激活；Scope 只负责范围检测，透视表现应由 Buff/Cue 提供。`ServerInitiated + ReplicateYes` 与 UE Ability 的服务器权威生命周期一致。

### 101421 不屈意志

CDO 字段含 `ExcludeDamageFromAbilities`、`HealthConversions`、`TreatBuffSpecs`、`SpecialSkillTag`、`ConversionCD`，Item 本身无 Scope/Buff 数值。说明它是“伤害/生命转换规则”型被动，实际转换公式必须从 Blueprint 图表或公共 BuffSpec 查证。不要擅自填入百分比；应在运行时用 ASC 属性捕获和 GameplayEffect Execution 验证。

### 101431 步枪

Item `Config_105`：EquipID `101401`，FireMode `0,1`，`bRoundRobin=false`，并有 `SimulateCurveFloat`。Equipment 给 `Weapon_PunisherElectronGun`，AmmoTag `Ability.Cost.Ammo1.1014`，最大 40；Mode 00/01 每发耗 1。`Ammo_101431_BP`、`Curve_101431_DamageDecay`、`Curve_101431_Impulse`、CameraShake 构成开火管线。Damage 曲线应以 causer/距离为输入；具体曲线点需从 Curve 资产读取，不能仅凭资产名推断数值。

### 101433 榴弹

CD 8s，Equip `101405`（`Weapon_PunisherHandgun`），目录含 `Timeline_101433_01`，其 Notify 应用 `BuffId=10143201`。ProjectileAgent `10143301`：速度 4000、重力 3、寿命 15、回收延迟 3、半径 Scene=5/Role=10，Enemy 碰撞 Template_05；Server 等待位置，客户端结果不作为最终命中。其 BaseDamage=0，而 Scope `10143301` 为半径 500、BaseDamage 45、Enemy Filter，且引用 `10143302`；因此伤害链很可能是 Projectile 命中 -> Scope/Ability 计算，必须保留两级引用。

## 8. BuffSpec、Effect、Cue 与 Timeline

1014 基础 `1014_BuffSpecTable.json` 行数为 0，不能据此断言英雄没有 Buff。已确认的 Buff 入口包括：`101433_01 -> BuffId 10143201`、`101461_01 -> 10146102`、`101481_01/02 -> 10148102`、Scope `10149202 -> BuffSpec 10149201`。应继续在 Common/GameMode BuffSpec、Ability 图表和运行时合并层查找其 GameplayEffect 类、Duration、Period、Stacking、Modifiers、Executions。

UE `GameplayEffect.h` 2256-2268 定义 Duration/Period，2280-2284 定义 Modifiers/Executions，2301-2332 定义 Stacking/Cues，2466-2513 定义 GE Components。推荐把伤害、资源、控制和视觉拆开：Damage GE 修改生命；Cost GE 修改 Ammo/能量；Buff GE 只授予标签/属性；Cue 处理命中、循环、结束和远端表现。

Timeline 是“动画时钟”而非 GE：`AnimNotify_TagNotify` 发事件标签，`ApplyBuff/RemoveBuff` 改变 ASC 状态，`SpawnScope`/`SpawnProjectile` 创建命中代理。`AbilityTask::OnDestroy` 必须清理 Notify 绑定和循环 Trace；`GameplayCueManager` 负责 Cue 生命周期与复制。

## 9. 网络预测与生命周期配置

客户端可预测的开火/投射物只提交输入和 PredictionKey；服务器在 `bServerWaitLocationInfo` 下复核位置、碰撞和 Cost。`GameplayPrediction.h` 64-112 的 PredictionKey 生命周期、175-208 的 ScopedPredictionWindow 解释了为什么不能在客户端单独应用最终 Damage GE。`AbilitySystemComponent.h` 1573-1615 的 TargetData/PredictionKey 复制用于把命中结果送回服务器。

能力必须遵循 `CanActivate -> CommitAbility -> 执行 Timeline/Task -> EndAbility`。Cost 或 Cooldown 提交失败时，撤销动画和已生成的 Scope；EndAbility 时移除 OwnedTags、取消子能力并回收 Summoner/Projectile。持续 Ability 的 `bIsCancelable`、`CancelWithOwnerTagRemove` 和 CDO Block/Cancel 标签必须形成闭环。

## 10. 推荐配置流程与校验清单

1. 在 Hero 表注册 ID、Class、基础属性和标签。
2. 创建 Equipment/Weapon/Ammo，验证 AmmoTag 唯一、Mode 扣费表和 OwnedTags 互斥。
3. 创建 AbilityTable 行，绑定输入、CD、UI、Log、EquipID 和 Granted BP。
4. 在 Ability CDO 配置 Tags、Net/Replication/Instancing、Cost/Cooldown 和取消规则。
5. 创建 Timeline/Notify，明确每个 ApplyBuff、SpawnScope、SpawnProjectile 的 ID。
6. 创建 Scope/Projectile/Summoner 行，配置过滤、形状、伤害 GE、Buff、Cue 和服务器验证。
7. 在 Common/GameMode 表补齐 BuffSpec -> GameplayEffect；若没有证据，保留未知并在运行时日志确认。
8. 测试：空弹药、换枪中开火、预测回滚、重复命中、塔死亡、终极结束、远端 Cue、Scope 回收。

最终闭包应满足：AbilityTable 的每个 Asset 都能找到 BP；每个 EquipID 都能找到 Weapon；每个 AmmoTag 都有上限和扣费动作；每个 Scope/Projectile/Summoner ID 都能被引用资产解析；每个 Buff ID 都能追溯到 GameplayEffect 或明确标记为未解包来源。

## 10A. 字段级配置字典

下面的字段名来自 1014 JSON 的真实序列化结构。字段为空时仍有语义：空数组表示该层没有额外规则，`null` 表示继承默认实现或由蓝图提供，不能当作 0 伤害或永久效果。

### AbilityItem / Ability CDO

| 字段                                      | 含义与配置规则                                                                                              |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `AbilityTags`                           | 能力身份标签；用于查询、取消和日志，不是输入键。                                                                             |
| `AbilityLabels`                         | 编辑器/UI 分类标签；不参与激活门禁。                                                                                 |
| `ActivationOwnedTags`                   | 能力激活期间由 ASC 持有的标签，EndAbility 自动撤销。                                                                   |
| `ActivationRequiredTags`                | 激活前目标/自身必须拥有的全部标签。                                                                                   |
| `ActivationRequiredAnyTags`             | 激活前至少满足一个标签。101402/101492 使用该字段。                                                                     |
| `ActivationBlockedTags`                 | 命中任一标签则拒绝激活。                                                                                         |
| `CancelAbilitiesWithTag`                | 激活时取消已有匹配能力，适合换枪、滑铲、终极互斥。                                                                            |
| `BlockAbilitiesWithTag`                 | 激活期间阻断匹配能力，不会自动取消已运行实例。                                                                              |
| `CancelWithOwnerTagRemove`              | Owner 标签移除时结束衍生能力；101462/101482 使用。                                                                  |
| `NetExecutionPolicy`                    | ServerOnly、ClientPredicted、ServerInitiated 等执行权。101411/101483 为 ServerInitiated，101421 为 ServerOnly。 |
| `ReplicationPolicy`                     | 是否复制 Ability 实例；`ReplicateYes` 用于持续/可观察实例。                                                           |
| `InstancingPolicy`                      | 实例化策略（每 Actor/每执行/非实例）；1014 导出未显式覆盖时继承 CDO 默认。                                                       |
| `bIsCancelable`                         | 是否允许取消；取消必须走 EndAbility 清理 Task、Cue、OwnedTags。                                                       |
| `IsLoopAbility`                         | Marvel 自定义持续输入循环；不能替代 GAS 的结束回调。                                                                     |
| `GrantedAbility`                        | 要授予 ASC 的 BlueprintGeneratedClass，ObjectPath 中的 `.1/.3` 是导出对象索引。                                     |
| `ActivateInput`                         | Marvel 输入枚举到 Ability 的桥接：`WeaponReload`、`Ability1/2`、`Ultimate`、`PrimaryAttack`、`MeleeAttack` 等。     |
| `BindInputConfigs`/`AbilityTriggers`    | 额外输入绑定或事件触发器；触发器应与 `Ability.Event.*` 标签保持一一对应。                                                       |
| `TimelineToPlayMontage`                 | 动画时间线数组；`AnimResIndex` 是武器/阶段选择索引。                                                                   |
| `ReadyCostStage`                        | 允许检查/预扣 Cost 的阶段；`None` 表示由蓝图显式提交。                                                                   |
| `CommitCooldownStage`                   | 提交冷却的阶段；101451 为 `Custom`，意味着蓝图必须明确调用 Commit。                                                        |
| `CostAttrActions`                       | 资源属性操作（Ammo、SkillEnergy、终极值）；与 GE 扣费只能选一个最终写入点。                                                      |
| `AbilityGameplayCues`                   | 能力级启动/循环/结束 Cue；命中 Cue 通常在 Scope/Projectile。                                                         |
| `CameraInterpAsset`/`EnableCameraShake` | 相机插值和屏幕震动表现，不应改变战斗判定。                                                                                |

### ScopeAgent 字段

| 字段 | 含义 |
|---|---|
|`ScopeAgent.ScopeAgent`|TargetActor 类；`MarvelAbilityTargetActor_Scope` 表示通用法术场。|
|`QuoteType`|法术场坐标来源：None、AttachedOwner、QuoteTransform 等。|
|`LifeWith`|是否跟随 Ability、Instigator、Alive 状态或连接；持续场必须定义销毁条件。|
|`LiftTime`/`TraceDelay`/`RecycleDelay`|启动延迟、存活时间、回收延迟；`-1` 常表示随宿主结束。|
|`TracePeriod`/`TracePolicy`|周期检测频率和追踪策略；0.1 是每 100ms 重算。|
|`QuantityLimitStrategy`|同类 Scope 数量统计和上限，防止技能重复生成。|
|`TraceType`/`Radius`/`HalfHeight`/`BoxSize`|几何形状及尺寸；Sphere 半径单位为 Unreal 厘米。|
|`HorizontalAngleDegree`/`VerticalAngleDegree`|扇区几何角；Sphere 配置仍保留默认角度字段。|
|`ShapeOffset`/`RotationType`/`CheckDir`/`AimDirType`|形状偏移、朝向来源、检查方向和瞄准候选。|
|`TraceMode`/`bMulti`/`ResultSortMode`|单/多目标、Overlap/Sweep 以及命中排序。|
|`TraceRule`|Self/Teammate/Enemy/Scene 模板和自定义碰撞过滤。|
|`TraceRequirements`/`BuffRequirements`|标签查询门禁；空查询代表不增加额外门禁。|
|`Occlusion`|遮挡起点、终点、门、可见性通道设置。|
|`AdvanceParams`|服务器回滚、Trace 加速器、去重、合并 Tick 等网络/性能选项。|
|`BaseDamage`|基础伤害、百分比生命、额外护盾、ApplyFilter、DamageEffect、曲线和暴击倍率。值为 0 时必须检查 Ability/Projectile/引用 Scope。|
|`BuffInfos`|每个命中目标要应用的 BuffSpec、目标过滤、移出范围时是否移除、唯一应用规则。|
|`BuffSpecs_ToSelf`|场创建者自身获得的 Buff；不要误放入目标 BuffInfos。|
|`RemovalBuffIDs`|Scope 结束时显式移除的 Buff ID。|
|`UniqueApplyRules`/`MaxApplyTimes`|重复命中策略和最多应用次数；可在达到上限时结束 Scope。|
|`bCommitCostPerTrace`/`bEndScopeWhenCostFailed`|每次周期是否扣 Cost，以及扣费失败是否结束场。|
|`GameplayCues`/`bEnableRemoteClientCue`|范围启动/循环/命中表现及远端客户端是否播放。|

### SummonerAgent 字段

| 字段 | 惩罚者值/含义 |
|---|---|
|`Id`/`SummonedName`/`Desc`|稳定 ID、显示名、设计描述。|
|`MaxNum`|同时存在数量：杆子 3、滑轮 1、炮台 1。|
|`MaxHealth`/`MoveSpeed`|召唤物属性；速度 620 是通用移动字段，不代表炮台会移动。|
|`bNeedASC`|是否创建独立 AbilitySystemComponent；仅炮台 10146101 为 true。|
|`bNeedBuff`|是否初始化默认 Buff；三行均 false，Buff 由 Ability/引用层显式授予。|
|`bSupportRollback`|是否参与预测回滚；三行均 false，需服务器维护生成/销毁。|
|`ScopeQuote`/`AbilityQuote`|召唤物附带的 Scope/Ability ID 列表；当前行为空，说明由 BP/Weapon 运行时绑定。|
|`InitBuffIDs`|生成时直接授予的 Buff；当前为空。|
|`GameplayCues`|Start/Loop/Damaged/Death/End 生命周期 Cue。|

### Equipment / Weapon / Ammo 字段

`EquipmentTable` 的 `EquipID` 是能力到武器的中间键；`WeaponClass` 决定发射方式，`AmmoTag` 决定 ASC 资源属性，`MaxAmmoValue` 是上限，`bInitialEquip` 决定出生时选中，`WeaponOwnedTags` 决定激活门禁，`EquipSummoners` 将武器绑定到召唤物，`GameplayCues` 提供武器 Loop 表现。Ammo 蓝图的职责是把 FireMode 转成消耗动作；步枪/霰弹 Ammo CDO 分别由 `Ammo_101431_BP`、`Ammo_101441_BP` 提供，终极飞弹由 `Ammo_101482_BP` 提供。解包行中 `AmmoCostSpecs` 的每个 Mode 消耗 0 或 1，Mode 未列出时不能推断默认扣费。

### Timeline/Notify 字段

`AnimTimeline.SequenceLength` 是秒；`MontagePath` 是实际 AnimMontage；`AnimSections` 是跳转段；`AnimNotifyTracks` 是通知轨道。101403 Shotgun Notify 发 `Ability.Event.101403.CheckReload`；101451 SpawnProjectile 写 `ProjectileId=10145101`、`InitLocationType=Left`、Socket=`MuzzleFlash_ZiplineLauncher`；101491 SpawnScope 写 `ScopeId=10149101`；101461/101481 的 Apply/RemoveBuff 分别控制塔/终极状态。CameraShake Notify 只做表现，不能承担 Commit 或伤害逻辑。
